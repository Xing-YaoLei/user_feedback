# 巡检单批量填报 + 本地模拟门户

纯 Python 标准库实现，无第三方依赖。两个程序通过网页表单（`application/x-www-form-urlencoded`）
和查询页 HTML（数据放在 `data-*` 属性中）交互，模拟真实门户的录入与查询。

## 组成

| 文件 | 作用 |
| --- | --- |
| `portal_server.py` | 本地模拟门户：表单录入、查询页、单号唯一、两种超时故障注入，SQLite 持久化 |
| `batch_submit.py` | 批量填报程序：读维修组 CSV，逐行网页录入，超时后查门户恢复，断点续跑 |
| `tests/test_e2e.py` | 8 个端到端测试，起真实子进程覆盖全部状态与恢复路径 |
| `demo/run_demo.sh` | 一键演示：正常单、非法单、两种超时、内容冲突、中途 kill、门户宕机重启 |
| `demo/*.csv` | 演示用维修组巡检单、门户预置数据、中途退出数据 |

## 快速开始

```bash
# 一键演示（自动起门户、配故障、填报、制造超时/kill/宕机、重跑恢复）
bash demo/run_demo.sh

# 或手动操作
python3 portal_server.py --port 8765 --data-dir ./portal_data
curl -X POST http://127.0.0.1:8765/admin/faults \
  -H 'Content-Type: application/json' \
  -d '{"pre_write_timeout":["XJ-003"],"post_write_receipt_lost":["XJ-004"],"fault_delay":6}'
python3 batch_submit.py --csv demo/inspection_orders.csv \
  --base-url http://127.0.0.1:8765 --state-dir ./run_data --timeout 4
# 出现"仍待确认"后，直接重跑同一条命令即可恢复

# 测试
python3 -m unittest -v tests.test_e2e
```

浏览器可打开 `http://127.0.0.1:8765/`（录入表单）、`/query`（查询页）、
`/admin`（已登记记录与故障配置）。

## 门户的保证

1. **单号只登记一次**：`order_no` 是 SQLite 主键。重复提交返回 HTTP 409，
   响应页带原始登记内容和回执，门户记录永不被覆盖。
2. **写入前超时**（`pre_write_timeout`）：按配置的休眠时长挂起请求且**不写库**，
   之后返回 504。客户端在休眠期内看到的是请求超时。
3. **写入后回执丢失**（`post_write_receipt_lost`）：**先写库提交**，再挂起并
   直接断开 TCP 连接，不返回任何 HTTP 响应。
4. **故障窗口**：故障按单号配置，首次命中后开启一个 `fault_delay` 秒的窗口，
   窗口内该单号的请求（含客户端立即重试）持续失败；窗口过后自动解除并清理，
   所以正常重跑时故障必然已经消失。配置接口：
   `POST /admin/faults`，JSON `{"pre_write_timeout": ["单号"], ...}`。
5. 数据落在 `--data-dir/portal.sqlite3`，门户进程重启后记录仍在。

## 批量程序的恢复协议

每张单先做本地字段校验（空值、日期格式、结论枚举），不过则记
**字段校验失败**且不联系门户。校验通过后：

```
POST /submit 网页表单
├─ 200 成功           → 已登记（读取响应页回执）
├─ 400 校验失败       → 字段校验失败
├─ 409 已存在         → 取响应页中的门户记录做字段比对
└─ 超时/连接断开      → GET /query 按单号查门户（失败则有限重试）
   ├─ 查到，设备编号+巡检日期+结论三项全一致
   │     → 已登记，把门户原回执补进结果表（不重新提交）
   ├─ 查到，但任一字段不一致
   │     → 内容冲突，保留门户记录，结果表逐项注明本地/门户差异
   └─ 查不到 → 才重新提交（最多两轮 POST，每轮失败后都先查门户）
         两轮后仍无法确认 → 仍待确认
```

- 只比对**设备编号、巡检日期、结论**三项（巡检员、备注不参与一致性判断）。
- 每处理完一行立即原子落盘 `state.json` 和 `result.csv`。中途被 kill、异常退出、
  门户宕机后重跑：已终态（已登记/字段校验失败/内容冲突）的行直接跳过；
  **仍待确认**的行重跑时先查门户，走同一套"查到比对、查不到才重提"的流程。
- 单行出问题不影响后续行；存在"仍待确认"时进程退出码为 3，全部终态为 0。

## 四种结果状态

| 状态 | 含义 |
| --- | --- |
| 已登记 | 门户中存在且三项字段一致，结果表含门户回执编号 |
| 字段校验失败 | 本地或门户校验不通过（原因写入"说明"列），未产生登记 |
| 内容冲突 | 门户已有同单号但字段不一致，门户记录保留，需人工裁决 |
| 仍待确认 | 两轮提交/恢复查询后仍无法确认门户状态，重跑同一命令即可继续 |

结果表 `result.csv` 列：巡检单号、状态、设备编号、巡检日期、结论、回执编号、说明。

## 输入 CSV 格式

UTF-8（带 BOM 亦可），必需列：`巡检单号,设备编号,巡检日期,结论`，
可选列：`巡检员,备注`。日期必须 `YYYY-MM-DD`，结论限 `合格/不合格/待复检`。
