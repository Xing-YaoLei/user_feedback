# 班次设备运行时长统计

按班次日历，把设备状态变化事件（JSONL）切成每条产线在各班次内的状态区间，统计
**运行 / 停机 / 未知** 三种时长（秒），并输出可回溯到原始事件的区间明细。

## 快速开始

```bash
# 正式运行
python3 -I src/shift_report.py --events data/events.jsonl --shifts data/shifts.csv --outdir out

# 内置自测（乱序、去重、同时刻取最大序号、带入前置状态、未知开头、跨午夜、时区换算、秒数守恒、事件追溯）
python3 -I src/shift_report.py --selftest
```

运行后生成：

- `out/shift_summary.csv` — 每班每线的三种时长汇总
- `out/intervals.jsonl` — 区间明细，每个区间带状态、起止、秒数和来源事件行号

## 输入格式

### 事件 JSONL（每行一个 JSON 对象）

| 字段 | 说明 |
| --- | --- |
| `line_id` | 产线编号（别名 `line` / `lineId`） |
| `timestamp` | 带时区偏移的 ISO 8601 时间，如 `2026-11-12T21:55:00+08:00`、`2026-11-12T13:55:00Z`、无冒号偏移 `+0800` 也可（别名 `time` / `ts` / `event_time`） |
| `seq` | 设备序号，整数（别名 `sequence` / `device_seq` / `serial`），缺失按 0 并告警 |
| `status` | 设备状态（别名 `state` / `device_status`） |

状态归一化（大小写不敏感）：

- 运行：`RUNNING` / `RUN` / `UP` / `ON` / `运行` / `运行中` / `开机`
- 停机：`DOWN` / `STOP` / `STOPPED` / `OFFLINE` / `FAULT` / `停机` / `停止` / `故障` / `关机`
- 未知：`UNKNOWN` / `UNK` / `N/A` / `未知`，以及任何无法识别的状态（会告警）

### 班次日历 CSV（UTF-8，可带 BOM）

| 字段 | 说明 |
| --- | --- |
| `shift_id` | 班次编号 |
| `start` / `end` | 带时区偏移的 ISO 8601 时间 |
| `line_id` | 可空；空行是全局班次，对所有产线生效；产线专属行优先于全局行 |

`end` 不晚于 `start` 时按**跨午夜**处理（end 顺延一天，沿用 end 自身偏移）。

## 统计规则

1. **乱序与重复**：事件先按产线、时间排序。完全相同的 `(时间, seq, 状态)` 视为重复，保留第一条并计数。
2. **同时刻仲裁**：同一产线同一时刻有多条事件时，以**最大 `seq`** 的事件为准；seq 相同而状态冲突时告警，以后到者为准。
3. **状态持续**：一次事件的状态持续到下一次变化事件。
4. **班次开头带入前置状态**：班次开始时，取该产线在班次开始前最后一条事件的状态（无论距今多久）；此前没有任何事件时，班次开头到首条事件之间记为 **UNKNOWN**。
5. **边界事件**：恰好落在班次开始时刻的事件从班次开头生效；恰好落在班次结束时刻的事件属于下一区间，本时段不产生零长区间。
6. **裁切**：所有区间按日历中的实际起止时间裁切，支持跨午夜班次。
7. **守恒校验**：`运行 + 停机 + 未知 = 班次实际时长（秒）`，不满足时进程以非零码退出并打印差异。
8. **时间渲染**：输出时间按班次日历使用的时区偏移渲染（计算内部统一换算 UTC，不同偏移写法的同一时刻会被正确识别为同一时刻）。
9. **亚秒精度**：事件时间支持小数秒；时长为整数秒时输出整数，否则保留最多 6 位小数。

## 输出格式

### `shift_summary.csv`

`line_id, shift_id, shift_start, shift_end, shift_seconds, running_seconds, down_seconds, unknown_seconds`

### `intervals.jsonl`（每行一个区间）

| 字段 | 说明 |
| --- | --- |
| `line_id` / `shift_id` / `segment_no` | 产线、班次、班内区间序号 |
| `start` / `end` / `duration_seconds` | 区间起止与秒数 |
| `status` | `RUNNING` / `DOWN` / `UNKNOWN` |
| `source_line` | 支撑该区间状态的事件在原始 JSONL 中的行号；UNKNOWN 区间为 `null` |
| `source_event` | 来源事件的原始时间、seq、状态；UNKNOWN 区间为 `null` |

## 样例：21:55 停机、22:00 换班、22:10 恢复

`data/` 中的样例覆盖该场景（22:00 换班，白班 08:00–22:00、夜班 22:00–次日 08:00）：

| 产线 | 班次 | 班次时长(s) | 运行(s) | 停机(s) | 未知(s) |
| --- | --- | --- | --- | --- | --- |
| L1 | DAY | 50400 | 50100 | **300（5 分钟，归前班）** | 0 |
| L1 | NIGHT | 36000 | 35400 | **600（10 分钟，归后班）** | 0 |
| L2 | DAY | 50400 | 19800 | 25200 | 5400（首条事件 09:30 才出现） |
| L2 | NIGHT | 36000 | 0 | 36000（带入白班 15:00 的停机状态） | 0 |
| L3 | D3 | 50400 | 0 | 0 | 50400（全天无事件） |

样例事件故意乱序、含重复行和同时刻不同 seq 的记录（21:55 的 seq=1 RUNNING 被 seq=2 DOWN 覆盖），
并混入 `Z` 与 `+08:00` 两种偏移写法。
