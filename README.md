# pro20 采集盒帧采集与重放

采集盒帧的在线接收、原始字节落盘、解码统计与离线重放。在线接收和文件重放
共用同一个 C++ 流式解码器（`pro20::FrameDecoder`），因此同一段录制数据无论
在线处理还是事后重放、无论按什么大小切块，结果完全一致。

## 帧格式

```
A5 5A | 长度(LE16) | 载荷(长度字节, 4..256) | CRC32(LE32)
```

- 整数一律小端。
- 载荷开头为 16 位设备号、16 位序号，其余为有符号 16 位读数。
- CRC32 为 ZIP 变体（poly `0xEDB88320`，初值/结果异或 `0xFFFFFFFF`），只校验载荷。
- 输入块可断在帧的任意位置；解码器持有跨块状态。
- 长度非法（<4 或 >256）或 CRC 错误：记录该帧起始字节（`A5`）在整条流中的
  绝对偏移，然后扫描下一个 `A5 5A` 重新同步。

## 缺号统计（按设备分别跟踪）

- 65535 之后接 0 视为正常连续（无符号回绕减法天然处理）。
- 与上一帧序号相同视为原样重发，只计一次重发，不算缺号。
- 其它跳变累计缺失序号数并记一次缺号事件。

## 线程与反压

```
读取线程 → [原始字节队列, 有上限] → 解码线程(原始落盘 + 解码)
                                  → [解码帧队列, 有上限] → 写入线程
```

- 两个队列都是固定容量阻塞队列。队列满时上游阻塞：写入端短时跟不上，
  读取端就暂停读取，下游恢复后自动继续。
- 在途数据内存上限 = `rawQueueChunks × readBlockSize` +
  `parsedQueueFrames × 单帧上限(264B)`，整班运行也不会无限积压。
- 写入失败或来源读取错误（`ByteSource::hadError()`，区别于正常 EOF）立即
  关闭队列停机，不向内存继续堆积。
- 已知边界：停机唤醒依赖来源的 `read()` 能返回。文件与内存来源可立即返回；
  若将来接入阻塞且不可取消的串口/TCP 来源，需为 `ByteSource` 增加超时/取消
  机制，否则来源卡死时 `wait()` 无法靠队列关闭中断。

## 构建

有 CMake：

```sh
cmake -S . -B build && cmake --build build && ctest --test-dir build
```

无 CMake（本机已验证）：

```sh
./build.sh
```

## 运行

```sh
# 模拟采集盒在线接收：原始字节写 run/raw.bin，解码结果写 run/frames.txt
./out/capture_demo run

# 用同一份原始字节重放，切块大小可任意（1 字节到数 KiB）
./out/replay run/raw.bin 1
./out/replay run/raw.bin 4096
```

不同切块大小的好帧数、错误偏移、各设备缺号/重发统计完全相同。

## 目录

```
include/pro20/   公共头（解码器、缺号跟踪、队列、来源、录制器、管道）
src/             实现
app/             capture_demo（在线）、replay（重放）
tests/           单元测试（切块不变性、错误定位、回绕/重发/缺号、反压）
```
