# 站点观测日报批处理

按站点、日期汇总观测明细，对照上报计划输出缺报情况与精确分位数。

## 用法

```bash
python3 -I daily_report.py \
  --details   观测明细.csv \
  --plan      上报计划.csv \
  --summary-out   汇总.csv \
  --unplanned-out 计划外.csv \
  [--chunk-size 150000]
```

仅使用 Python 标准库，无需安装依赖。`-I` 以隔离模式运行，避免当前目录下的同名模块被意外导入。

## 输入格式

**观测明细 CSV**（4 列，表头支持中英文列名，支持 UTF-8 BOM）：

| 列 | 可接受表头 | 说明 |
|---|---|---|
| 站点 | 站点 / site / station | 非空 |
| 日期 | 日期 / date | `YYYY-MM-DD`，校验合法日历日期 |
| 记录编号 | 记录编号 / 编号 / record_id / id | 非空 |
| 读数 | 读数 / reading / value | 整数，支持负数与 0 |

**上报计划 CSV**（3 列）：站点、日期、应报数（非负整数）；同一站点+日期不允许重复。

空行会被跳过；字段数不符、读数/日期无法解析、计划重复等错误会报出
**文件名 + 行号 + 列名 + 原始内容**，进程以退出码 2 中止。

## 输出

**汇总 CSV**：`站点,日期,应报数,实报数,缺报数,读数总和,p50,p95`

- 去重规则：同一站点+日期+记录编号的重传只计一次；编号不同即使读数相同也分别计入。
  同编号重传但读数不一致时，以**首次上报**为准，被忽略的冲突会在 stderr 告警（附行号）。
- 计划内当天一条明细都没收到：仍输出一行，实报数 0、分位数留空。
- 实报数超过应报数时，缺报数记 0（不为负）。
- 分位数采用**最近秩法**（nearest rank，下标 = ⌈p·n⌉），纯整数运算、无浮点误差。

**计划外 CSV**：`站点,日期,记录编号,读数`，列出站点+日期不在计划中的去重后记录。

## 失败安全

输出先写入临时目录，全部解析与计算成功后才 `os.replace` 原子发布。
任何输入错误都不会覆盖上一次成功生成的两个结果文件。

## 内存与实现

外部排序 + 多路归并，峰值内存与总记录数无关：

1. 明细流式读入，按 15 万行一块排序落盘为临时归并段；
2. `heapq.merge` 归并时同编号记录天然相邻，O(1) 内存完成去重；
3. 读数存于 `array('q')`（8 字节/值，200 万条约 16 MiB），超 int64 自动回退普通列表。

实测 200 万条全部集中在同一站点同一天：**峰值 RSS 约 82 MiB**（上限 192 MiB），
耗时约 5 秒。临时归并段占用磁盘，处理结束自动清理；`--chunk-size` 可调小以进一步降低内存。
