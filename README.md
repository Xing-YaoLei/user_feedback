# 分布式快照模块(distributed-snapshot)

Node.js + TypeScript 实现的分布式快照协调层:在乱序、重复、可延迟的传输上,
为固定名单的节点集群提供多轮并发的一致全局快照(Chandy-Lamport / Lai-Yang 风格)。
成功结果包含各节点的本地截面,以及截面之间每条通道的在途消息。

## 运行与测试

要求:Node.js ≥ 22.6(直接使用内置 TypeScript 类型擦除,无需安装编译器;开发环境为 Node 26)。

```bash
npm test   # node --test tests/,断言失败时非零退出
```

测试全部使用本地合成数据与调用方适配器(`src/harness.ts`),不依赖真实外部服务。

## 目录结构

- `src/snapshot.ts` — 核心模块:`SnapshotNode`、线上消息类型、快照结果类型(模块入口为 `src/index.ts`)
- `src/harness.ts` — 本地合成传输适配器:在途队列支持乱序/重复/延迟投递,并收集发送/接收/记录轨迹
- `tests/verify.ts` — 轨迹复验器:用发送/接收轨迹独立复验成功切面与通道记录
- `tests/snapshot.test.ts` — 场景测试(见下)

## 设计要点

- **业务消息携带轮次标记**:每条业务消息携带发送方发送时已记录的轮次列表。
  接收方在处理业务效果(同步回调)之前,先对标记中自己尚未记录的轮次补做本地截面。
  因此捕获边界由业务消息携带的轮次信息决定,与控制消息(公告/通道报告)的到达顺序无关;
  控制消息只负责传播轮次名单与发送计数,晚到、乱序、重复都不影响切面正确性。
- **一致切面**:若某消息的接收效果计入接收方截面,则其发送必然计入发送方截面
  (发送方已记录的轮次会随消息标记传播,接收方被迫先记录再处理)。
- **通道记录与完成证明**:发送方记录轮次时记下对每个邻居的“截面前发送计数”并告知接收方;
  接收方按 `(from, seq)` 去重,把截面前消息分类为“已吸收”(计入本地截面)或
  “在途”(计入通道记录)。某通道截面前发送的消息全部分类完毕(分类数 == 发送方计数)后,
  该通道才被证明完成;所有通道证明完成后节点才向发起者上报,发起者收齐名单内全部报告后
  汇总出全局状态。
- **重复与失败隔离**:业务消息按 `(from, seq)` 去重,重复投递不进入业务回调也不重复分类;
  单轮取消、容量不足、权威节点代次变更都会使该轮明确失败并广播中止,
  其他轮次与业务投递继续推进;轮次结束后通道载荷与轮次标记即被回收,
  后续业务消息不再携带已结束轮次的标记。

## 主要 API

```ts
const node = new SnapshotNode({
  id, roster, transport,          // 节点身份、固定名单、传输适配器
  captureState: () => ...,        // 调用方提供的本地状态捕获回调
  onBusiness: ({from, seq, payload}) => ...,  // 本地消息处理回调(同步完成状态修改)
  maxRounds, authorityEpoch,      // 容量上限、权威节点代次
  onRoundComplete, onRoundFailed, // 结果/失败回调
  onEvent,                        // 轨迹钩子(测试用)
});

node.sendBusiness(to, payload);   // 业务发送(自动携带轮次标记)
node.receive(msg);                // 传输适配器投递入口
node.startRound(roundId);         // 以本节点为发起者开始一轮快照
node.cancelRound(roundId);        // 取消单轮
node.setAuthorityEpoch(epoch);    // 权威代次变更,使代次不符的活动轮次失败
```

成功结果 `SnapshotResult`:`states`(各节点本地截面)+ `channels`(键 `from->to` 的在途消息记录)。

## 测试场景

1. **两个重叠快照 + 交错业务回复**:A、B 同时各自发起一轮,业务 ping/pong 交错;
   包含“先到的截面后消息”(携带轮次标记的业务消息先于公告到达,接收方依据标记补做截面)
   与“迟到的截面前消息”(无标记消息在接收方记录后才到达,恰好落入通道记录);
   全程乱序 + 约 1/4 重复投递,最后用发送/接收轨迹复验两个成功切面与全部通道记录。
2. **单轮取消**:r1 被取消并明确失败,r2 与业务投递不受影响,失败轮次不污染 r2 的结果。
3. **容量不足**:节点容量占满时新轮次明确失败并通知发起者,其他轮次照常完成。
4. **权威节点代次变更**:活动轮次明确失败、过期公告被拒绝,新代次下可重新快照成功。
5. **重复投递只生效一次**:业务回调与回复均不重复执行。
6. **无业务流量**:快照照常完成,通道记录为空。
